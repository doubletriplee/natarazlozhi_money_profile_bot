# Архитектура MVP

```text
Telegram long polling
        │
        ├── первое изображение → согласие → анкета
        ├── GeoNames → Swiss Ephemeris → правила → зашифрованный результат
        ├── изображение аватара + утверждённое описание
        └── предложение полного разбора → личный Telegram с готовым сообщением

Caddy → 127.0.0.1:18080 → aiohttp (/healthz, /privacy, /terms, /source)
SQLite WAL: пользователи, согласия, профили и события
```

PDF и шкала оценки в текущем пользовательском сценарии не используются. Команда `/profile`
повторно отправляет изображение аватара, его описание и финальное предложение. Username продавца
берётся из единой настройки `SUPPORT_USERNAME`; ссылка кодирует готовый текст сообщения.

Персональные значения шифруются AES-256-GCM с отдельным контекстом каждого поля. Telegram ID ищется
по HMAC-SHA256 и не хранится открыто. Приложение не сохраняет полные Telegram updates и callback-тела.

Методика, правила и факты карты версионируются отдельно. Сохранённый профиль не пересчитывается
при обновлении движка.
