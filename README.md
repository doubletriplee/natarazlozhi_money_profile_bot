# Telegram-бот «Денежный аватар»

Публичная AGPL-3.0 реализация Telegram-бота, который детерминированно рассчитывает
астрологический денежный профиль по локальной Swiss Ephemeris. В работающем приложении нет
LLM и вызовов OpenAI API.

## Возможности

- стартовый экран с явным согласием на обработку данных, без возрастного ограничения и без
  фиктивной записи подтверждения совершеннолетия;
- кнопочный выбор даты (десятилетие → год → месяц → день) и времени
  (час → диапазон минут → точная минута) с ветками точного, примерного и неизвестного времени;
- нейтральные по полу вопросы анкеты; завершённый шаг заменяется следующим в том же сообщении,
  а введённое пользователем название города удаляется после обработки;
- одноразовое напоминание через час, если следующий шаг анкеты не пройден;
- локальный поиск GeoNames `cities500` и IANA timezone, включая ввод `Россия, Москва`;
- Плацидус с безопасной веткой без домов для полярных широт и неоднозначного времени;
- бесплатная карточка денежного аватара с кнопкой «Узнать силу» и автоматическим
  предложением через час, если кнопку не нажали;
- независимые повторные расчёты через `/start`: каждый набор данных рождения создаёт отдельный
  профиль и может быть открыт или оплачен независимо от предыдущих аватаров; после расширенного
  результата доступна кнопка «Рассчитать другой аватар»;
- единый экран разбора за 149 ₽: в test — явная пометка об отсутствии списания, в production —
  email для чека, одноразовый счёт Robokassa, выдача после подписанного подтверждения платежа и
  понятная страница возврата в Telegram с автопереходом и явной кнопкой;
- закрытый staging-сценарий Robokassa с тестовыми паролями, email для чека, одноразовым счётом и
  внешней платёжной страницей без списания денег, одним подписанным `ResultURL` и страницей возврата
  в бот с автопереходом и явной кнопкой;
- закрытый `APP_ENV=pilot` с боевыми реквизитами, allowlist одного владельца и отдельным
  подтверждаемым переключателем реальных счетов;
- двухэтапный переход в публичный production: сначала открытый доступ с выключенными счетами,
  затем отдельное подтверждаемое включение оплаты для точного прошедшего CI commit;
- активные «Робочеки СМЗ», передача email и полной номенклатуры для автоматического чека оплаты,
  а также состава возврата для возвратного фискального чека;
- атомарный запуск возврата Robokassa без повторной отправки при двойном подтверждении и
  обязательная ручная сверка при неопределённом ответе провайдера;
- приоритетная доставка оплаченных заказов с контролем работоспособности через `/healthz`;
- защита расчёта от повторного нажатия одним пользователем и ограниченная общая очередь тяжёлых
  вычислений;
- мягкое ограничение частоты Telegram-сообщений и нажатий отдельно для каждого пользователя;
- защитные HTTP-заголовки и отдельное ограничение частоты публичных запросов по адресу клиента;
- автоматическая шифрованная копия SQLite каждые 6 часов с пробным восстановлением и контролем
  свежести через `/healthz`;
- раздельные сроки хранения: 30 дней для email и временных платёжных ссылок, не менее пяти лет
  для минимального реестра реальных оплат; после удаления персональных данных и завершения срока
  удаляется весь связанный технический журнал заказа;
- предложение полного разбора за 990₽ по кнопке после платного результата либо автоматически
  через час, если кнопку не нажали, с переходом в личный Telegram;
- адаптивная главная страница магазина с составом и стоимостью разборов, порядком получения,
  реквизитами исполнителя из Публичной оферты и ссылками на юридические документы;
- изолированный SSH/SOCKS-шлюз для Telegram API на серверах без стабильного прямого маршрута;
- повторная выдача последнего сохранённого аватара через `/profile`;
- AES-256-GCM для персональных полей и HMAC-SHA256 для индексов;
- обязательная проверка Python-зависимостей на известные уязвимости в CI и минимальный runtime-образ
  без установщиков и сборочных пакетов;
- автоматические предупреждения GitHub об уязвимостях и еженедельные Dependabot-проверки Python,
  Docker и GitHub Actions;
- `/stats` на одном экране: шесть ступеней общей воронки по уникальным людям, доля оплативших
  и выбор периода; тестовый режим явно отделён от реальных оплат;
- уведомления о подтверждённых оплатах в личные чаты отдельно настроенных получателей, с очередью
  повторной отправки; `/myid` для подключения; [правила отчётности и уведомлений](docs/analytics.md);
- защищённый двухшаговый `/refund` для production-администраторов, `/delete_my_data`,
  публичные `/`, `/privacy`, `/consent`, `/terms`, `/source`, `/healthz`.

## Локальный запуск

Требуется Python 3.11 или 3.12.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
python scripts/build_geonames.py data/cities.sqlite3
money-profile-bot
```

Для создания трёх 32-байтных ключей:

```bash
python scripts/generate_keys.py
```

## Защищённая production-оплата

Развёрнутый сервер работает в публичном `APP_ENV=production`. 4 сентября 2026 года владелец прошёл
публичный пользовательский путь, включая повторный расчёт по другим данным, подтвердил закрытие
оставшихся юридических вопросов профильным юристом и разрешил создание реальных счетов. Для реальной
оплаты окончательно выбрана только Robokassa; Telegram Stars не используются, не планируются и не
рассматриваются как альтернатива. Владелец осознанно принял известный риск ограничения или удаления
бота из-за того, что автоматическая продажа цифрового результата через внешний платёжный сервис не
соответствует правилам Telegram.

Рабочее состояние оплаты хранится только в закрытом серверном env. Включение и аварийное отключение
выполняются привязанным к точному commit запросом `scripts/request_production_payments.ps1` и затем
единственным штатным `scripts/deploy.ps1`; прямое редактирование флагов не используется.

Полный production-администратор получает доступ и к статистике, и к подготовке и подтверждению
возвратов Robokassa. Новый ID добавляется к существующему списку, не заменяя владельца, только
привязанным к точному commit запросом и следующим штатным deploy:

```powershell
pwsh -NoProfile -File scripts/request_production_admin.ps1 -State Add `
  -TelegramId <telegram_id> -AcknowledgeFullAdminAccess
pwsh -NoProfile -File scripts/deploy.ps1
```

Отзыв доступа выполняется тем же сценарием с `-State Remove`; удалить последнего администратора
нельзя.

Зафиксированное решение и его границы описаны в
[документе о платёжной модели](docs/payment-model.md).

Для закрытой проверки Robokassa используется отдельный `APP_ENV=staging` на основе
`.env.staging.example`. Он требует `PAYMENT_MODE=robokassa`, `ROBOKASSA_TEST_MODE=true`, тестовые
пароли №1/№2, отдельные ключи шифрования и непустой `TEST_ACCESS_TELEGRAM_IDS`. Основные платёжные
пароли и реальные списания в staging не используются.

После активации магазина закрытый боевой контур готовится отдельно на основе
`.env.pilot.example`. `APP_ENV=pilot` принимает только рабочую Robokassa, требует непустой
`PILOT_ACCESS_TELEGRAM_IDS`, три основных пароля и подтверждение принятого платформенного риска.
Первичная настройка всегда оставляет `LIVE_PAYMENTS_ENABLED=false`: бот закрыт allowlist, а новые
реальные счета не создаются. Публичный production этим режимом не включается.

Серверный staging настраивается `scripts/configure_staging.ps1`: секреты принимаются как
`SecureString`, передаются через стандартный ввод SSH, не записываются в Git и проверяются без
перезапуска сервиса. После успешной настройки применяется только штатный `scripts/deploy.ps1`.
Закрытый pilot аналогично подготавливается `scripts/configure_pilot.ps1`; сценарий не включает
списания и не перезапускает сервис.

3 сентября 2026 года токен pilot-бота и три основных пароля Robokassa, использованные при первичной
настройке через канал переписки, заменены и повторно применены через безопасный интерактивный ввод.
Новые значения не публиковались в чате, Git или журналах; создание реальных счетов после ротации
осталось выключено.

3 сентября 2026 года владелец сообщил о завершённой проверке профильным юристом и бухгалтером.
Для одной закрытой реальной операции разрешение создаётся через `scripts/request_pilot_payments.ps1`
и применяется только штатным `scripts/deploy.ps1`. Включение принимается лишь для единственного ID,
который одновременно находится в pilot- и admin-списках; аварийное отключение использует тот же путь.

3 сентября 2026 года владелец подтвердил снимком личного кабинета, что решение «Робочеки СМЗ»
одобрено ФНС и активно. В тот же день закрытая реальная оплата 149 ₽ создала ровно одну запись,
результат был доставлен с первой попытки, а владелец подтвердил исходный чек на email и в «Мой
налог». 4 сентября Robokassa завершила полный возврат, а владелец подтвердил зачисление денег и
возвратный чек в «Мой налог». Создание новых реальных счетов снова выключено. Закрытая проверка
полного платёжного и фискального цикла завершена; позднее публичные счета разрешены отдельным
production-запросом после smoke-проверки и юридического подтверждения.

[Методика версии 1.0](metodika-denezhnogo-profilya.md) и объединение двенадцати домов в десять
денежных аватаров подтверждены астрологом. Три [контрольные карты](docs/golden-cards.md) для точного,
примерного и неизвестного времени зафиксированы полными контрольными суммами и проверяются в CI.
4 сентября 2026 года владелец явно подтвердил все три результата; защищённый переход в production
устанавливает `GOLDEN_CARDS_APPROVED=true` только вместе с сохранением паузы новых счетов.

После подтверждения контрольных карт переход был подготовлен
`scripts/request_production_transition.ps1` и применён только штатным `scripts/deploy.ps1`.
Первый production-запуск снял Telegram allowlist и принудительно сохранил
`LIVE_PAYMENTS_ENABLED=false`. 4 сентября 2026 года публичный режим проверен, включая повторный
профиль, а профильный юрист закрыл оставшиеся юридические вопросы; владелец разрешил реальные счета.
Их рабочее состояние меняет только отдельный `scripts/request_production_payments.ps1`; откат и
отдельная команда отключения всегда запрещают создание новых счетов.

Для редакторской проверки общий экран покупки и все десять текстов платного результата собраны в
[одном файле](Тексты_разборов_за_149_для_проверки.md).
