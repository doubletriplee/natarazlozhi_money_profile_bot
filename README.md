# Telegram-бот «Денежный потенциал»

Публичная AGPL-3.0 реализация Telegram-бота, который детерминированно рассчитывает
астрологический денежный профиль по локальной Swiss Ephemeris. В работающем приложении нет
LLM и вызовов OpenAI API.

## Важное ограничение оплаты

Проект создаёт внешнюю ссылку Robokassa в рублях и после серверного подтверждения выдаёт
цифровой результат в Telegram. Такой сценарий не соответствует требованию Telegram использовать
Stars для цифровых товаров и услуг в ботах. Владелец проекта явно принял риск ограничения или
блокировки бота. Код не маскирует платёжный поток и не пытается обходить проверки платформы.

## Возможности

- анкета с ветками точного, примерного и неизвестного времени рождения;
- локальный поиск GeoNames `cities500` и IANA timezone, включая ввод `Россия, Москва`;
- Плацидус с безопасной веткой без домов для полярных широт и неоднозначного времени;
- десять денежных аватаров с отдельными изображениями бесплатного результата и оффера;
- версионированные факты карты, правила и шесть детерминированных текстов в едином PDF;
- отложенное на три минуты предложение полного разбора с изображением и ссылкой на личный Telegram;
- Robokassa Invoice API в RUB, email для автоматического чека, подписанный `ResultURL`;
- отдельный `PAYMENT_MODE=fake` для закрытого бесплатного теста без списания и чека;
- изолированный SSH/SOCKS-шлюз для Telegram API на серверах без стабильного прямого маршрута;
- идемпотентный платёжный журнал, очередь доставки, повторная выдача через `/profile`;
- возвраты Robokassa с двухэтапным подтверждением администратора;
- AES-256-GCM для персональных полей и HMAC-SHA256 для индексов;
- `/stats`, `/delete_my_data`, публичные `/privacy`, `/terms`, `/source`, `/healthz`.

## Локальный запуск

Требуется Python 3.11 или 3.12.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
python scripts/build_geonames.py data/cities.sqlite3
money-profile-bot
```

Для создания трёх 32-байтных ключей:

```bash
python scripts/generate_keys.py
```

## Настройка Robokassa

До подключения эквайринга закрытый test-бот запускается с `PAYMENT_MODE=fake`. В этом режиме
кнопка сразу создаёт заказ на 0 ₽ и ставит результат в очередь доставки, а первый пользователь,
отправивший `/start`, занимает единственный тестовый admin-слот при
`BOOTSTRAP_ADMIN_ON_FIRST_START=true`. Эти два параметра запрещены production-валидацией.

В личном кабинете нужно создать и активировать магазин самозанятого, подключить решение
автоматических чеков через «Мой налог» и установить:

- Result URL: `https://money.natarazlozhi.ru/payments/robokassa/result`, метод POST;
- тот же алгоритм хеша, что в `ROBOKASSA_HASH_ALGORITHM`;
- основные и тестовые пароли №1/№2, а для возвратов — Password3;
- фискализацию с номенклатурой услуги.

Бот передаёт позицию `Индивидуальный разбор «Денежный потенциал»`, `Tax=none`,
`PaymentMethod=full_payment`, `PaymentObject=service`. Тестовый режим Robokassa не списывает
деньги и не поддерживает `OpStateExt`; для проверки реального возврата нужен отдельный закрытый
бот с ценой 1 ₽ и боевым режимом Robokassa.

## Защитные блокировки production

Конфигурация `APP_ENV=production` не запускается без реквизитов оператора, утверждённого срока
хранения платёжного журнала, финальной версии юридических документов, подтверждения методики и
эталонных карт, всех ключей и реквизитов Robokassa. Отдельный флаг
`PAYMENT_PLATFORM_RISK_ACKNOWLEDGED=true` фиксирует принятое владельцем решение по оплате.

Методика в [metodika-denezhnogo-profilya.md](metodika-denezhnogo-profilya.md) пока имеет статус
черновика. Это не следует менять до профессиональной проверки астрологом.
